# Dependency-lock reproducibility hardening

This change closes the dependency-resolution caveat carried through PR8.

## Contract

- Generate the root npm workspace `package-lock.json` with npm `10.9.2`, matching the root `packageManager` declaration.
- Commit the lockfile.
- CI must install with `npm ci --ignore-scripts`; it must not fall back to `npm install`.
- Lockfile generation must not mutate root or workspace `package.json` files.
- The committed lockfile must be included in the executable/config artifact closure.
- The full source, PostgreSQL, boundary, secret-scan, manifest, and runtime-audit gates must remain green.

## Failure and repair ledger

### DL-001 — historical PR8 manifest correctly rejected package.json drift

Permanent-path run `39001134525`, job `117304102767`, head `5fe91304ec1f2a4bc60592091a4d82ccd16fcfb3` successfully pinned npm `10.9.2`, installed from the committed lockfile with `npm ci --ignore-scripts`, proved dependency declarations were unchanged, and passed all 42 source/unit tests. It then failed the historical PR8 artifact manifest because this hardening intentionally changed `package.json`.

The failure was valid evidence: the PR8 manifest remained an immutable record of the PR8 merge candidate and should not be rewritten to bless a later change.

Repair: keep `manifest:pr8` independently callable as historical evidence, but advance the active root `verify` gate to the new dependency-lock change-scope manifest. This preserves PR8 provenance while giving later dependency/config changes their own closure surface.

Earliest invalidated layer: verification/manifest composition. Runtime semantics were not implicated.
